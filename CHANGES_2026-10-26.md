## 2. Request 1: fixes and a review of the memory layer

### Code changes

**To-do list cut off** (`src/app/(tabs)/tasks.tsx`)
- Cause: the Schedules list was hidden with `display: 'none'`, but on Android the `RefreshControl` wrapper around it keeps `flex: 1`, so it still took half the screen.
- Fix: the Schedules list is rendered only while the Schedules segment is selected. (This is kept, and commented, in the redesign.)

**Oval press effect on tabs** (`src/app/(tabs)/_layout.tsx`)
- The tab button is a `PlatformPressable` with `pressColor="transparent"`; while pressed it draws the same oval pill as the selected tab, so the press feedback has the active shape instead of Android's circular ripple spilling past it.

**Swipe right to open the chat list** (`src/app/(tabs)/_layout.tsx`, `src/components/common/SidebarDrawer.tsx`, `package.json`)
- Added `react-native-drawer-layout` (`^4.2.12`). The tab layout is wrapped in a `Drawer`: slides with the content, 85% wide, a swipe can start anywhere on the screen (not just the edge), only on the Chat tab, and only a **rightward** swipe opens it (12 pt of horizontal travel; a mostly vertical move still scrolls, so code blocks and file chips in messages scroll first).
- Once open, a left swipe closes it from any tab; Android's Back button closes it before leaving the screen.
- `SidebarDrawer` became the drawer's content (its own `Modal` removed).

### Review delivered (no code)
- Read every doc to understand the memory layer's purpose and pipeline.
- Checked what the Feed, Ideas, and To-do endpoints actually return against real data, and found:
  - **Review wasn't happening:** 280 of 285 memories had never been reviewed, so manual approval wasn't a gate anyone used.
  - **Resends made duplicates:** one LinkedIn request sent four times became five differently worded tasks.
  - **The Feed's insights were noise:** its first card read "You finish 0% of what you plan".
- Recommended capture by conversation, auto-accept of confident memories, and write-time duplicate merging. All three were built in request 3.

## 4. Request 3: memory, chat titles, documents, Today (ADR-048, ADR-049)

Full rationale: `memory-layer-for-life/context for agent/DECISIONS.md`, ADR-048 and ADR-049.

### 4.1 Capture by conversation, not by message (backend)

- A chat is read for memories once it has been **quiet for 5 minutes** (`MEMORY_CAPTURE_QUIET_SECONDS`). Everything the user wrote since the last capture becomes **one unit** of evidence, processed in the pipeline loop (`QuietChatCapture` / `MemoryCapture`, watermark `chat_threads.memory_captured_through`).
- Each user line carries the assistant message it answered (`assistant_before`), and the unit carries what Cooper saved itself during it (`saved_by_assistant`). These are kept as context only; quotes (evidence) come only from the user's own lines.
- Lines that can't hold a memory alone (under three words, thanks, approvals like "yes, send it") travel as context.
- A line already sent in the last 24 hours (a **resend**) is dropped.
- A stretch with nothing else in it costs **no model call**.
- Existing chats start at their latest activity, so nothing is captured twice.
- Files: `app/services/memory_capture.py` (rewritten), `app/services/processing/runner.py` (`MaterializeHook`, `_persist_owned`, `QuietChatCapture`, `PipelineLoop.next_due`), `app/domain/conversation.py` (new), `app/repositories/chat_repository.py`, `message_repository.py`, `processing_run_repository.py`, `app/models/chat_thread.py`.

### 4.2 Extraction prompt 3 and contract 1.1 (backend)

- Chat units are marked `conversation_with_assistant`. Requests, questions, greetings, and approvals are not memories.
- Abstaining is now a normal outcome: the run ends as succeeded instead of held back. Held-back chat runs no longer fill To review.
- Every memory gets a short **`title`** for lists.
- A conversation gets a **`conversation_title`**, in the **same model call**. `ChatTitleHook` uses it to name a side chat once (`chat_threads.title_generated`). Until then the chat is named from its first message (`heuristic_title`): links are named for what they are, and polite openings are dropped.
- Both fields are required of the model. Payloads stored under contract 1.0 read them as null, through `_absent_as_null` before-validators.
- Files:
  - Prompt and contract: `app/integrations/extraction/prompt.py`, `app/integrations/extraction/base.py`, `app/schemas/extraction.py`, `app/domain/versions.py` (schema 1.1, builder "2").
  - Pipeline: `app/services/processing/extraction.py`, `app/services/processing/memory_builder.py`.
  - Evaluation and snapshot: `evaluation/fixture_extractor.py`; the regenerated snapshot `tests/contract/snapshots/extraction_output_schema.json`.

### 4.3 Auto-accept (backend)

- Rule `auto-accept/1`, in `app/domain/memory_policy.py` (new). A memory is saved **active**, with an `accepted` history entry naming the rule, when all of these hold:
  - confidence ≥ 0.8;
  - not sensitive;
  - not an abstention;
  - in the user's own words (a chat, a file, or a `Me:` line of an import).
- Everything else stays **proposed**, so To review holds only the exceptions.
- The brief counts only memories proposed in the last week.
- Off switch: `MEMORY_AUTO_ACCEPT_ENABLED=false`.

### 4.4 No duplicates: write-time reconciliation (backend)

- Before a memory is inserted, it is compared with the user's live, open memories of the same kind, using `pg_trgm` text similarity. It counts as a match when:
  - the similarity is **≥ 0.8**, or
  - it is **≥ 0.45** and both share a link (such as the same LinkedIn post).
- A match gets, instead of a new memory:
  - the new evidence and the entity links it lacked;
  - the new due date;
  - a **`mentioned_again`** history entry (a new event action);
  - acceptance, if the new reading is confident.
- Money notes are never merged: two notes of "103 auto" can be two rides.
- Drafts within one unit are compared with each other the same way.
- Files: `app/repositories/memory_repository.py`, `app/services/processing/memory_builder.py`, `app/domain/enums.py`.

### 4.5 Chat (backend + app)

- Starting a side chat reuses an empty one, and empty side chats are hidden from the list (`app/services/chat.py`, threads endpoint).
- Each message names the memories it is evidence for (`saved_memories`). Under your message the app shows **"Remembered: …"** chips with **Undo**, which retracts the memory (`app/schemas/app.py` `SavedMemoryResponse`, `app/api/v1/app_mappers.py`, `src/app/(tabs)/chat.tsx`).
- Every memory response carries a `title`: the extractor's, or the content without evidence-style phrasing (`app/services/queries.py` `MemoryView.title`, `app/schemas/memory.py`, `src/lib/memories.ts`).

### 4.6 Today instead of the old Feed (backend + app)

**`GET /me/today`** (`app/domain/today.py`, `app/services/today.py`, life schemas and endpoint) builds the cards without a model:
- **Next actions:** overdue items, items due or reminded today, promises to people, items due this week (at most five).
- **Promises.**
- **Today's and tomorrow's calendar events**, with what your memories say about the people they name.
- **One idea or goal to pick up again** each day.
- **Memories to confirm.**

**`GET /me/life`** now lists open questions apart (`questions`), and lists imported items still unconfirmed as `triage` (keep, done, or drop). Neither counts as a to-do or as overdue (`app/domain/life_state.py`, `app/services/life_state.py`, `app/repositories/life_repository.py`).

**Insights need evidence before they speak** (`app/domain/insights.py`, `app/services/insights.py`, `app/repositories/insight_repository.py`):
- A follow-through rate needs 5 items, at least one of them closed by you.
- A month's money total needs 5 notes, and so does the month it's compared with.
- People count only in memories about you and them, never in money notes, links, or working notes.

**App:**
- `src/components/feed/TodaySection.tsx` (new) and `src/app/(tabs)/feed.tsx`: Today first, then this week's insights and the scheduled results.
- `src/components/feed/InsightsSection.tsx` was restyled.
- `src/app/(tabs)/ideas.tsx`: your own ideas from memories, with **Explore with Cooper**, then the ready-made prompts.
- `src/components/tasks/TodoPanel.tsx`: separate **Questions** and **Triage** groups.
- `src/lib/api/today.ts` and `src/lib/api/types.ts`.

### 4.7 My files: documents Cooper reads (ADR-049) (backend + app)

- **Upload:** PDF, Word (.docx), text, or Markdown, up to 10 MB (`POST /me/documents`). The text is read **without a model**:
  - a PDF's text layer with `pypdf` (new dependency);
  - a .docx's paragraphs with the standard library, with limits against zip and XML bombs;
  - text files as they are.
  It is kept in ~1,500-character passages with full-text search. The same file twice is the same document.
- **Scanned PDFs** are refused with a clear message, unless `DOCUMENT_VISION_FALLBACK=true`. Then the model reads it once, which counts as one of the day's prompts.
- **Documents are not memories:** nothing is extracted from them.
- **Resume detection:** the first file that looks like a resume (by its name or its sections) becomes **the resume**. At most one.
- **Cooper's tools:** `read_document` reads a whole file (`resume` finds the resume) and `search_documents` finds passages by words. The context lists documents by title. The job-application prompt reads the resume before drafting (assistant prompt 1.8).
- **Delete** removes every passage at once: Cooper can't read anything of it afterwards. Documents are deleted with the user and included in the export.
- **App:**
  - **My files** screens: `src/app/files/index.tsx` and `src/app/files/[id].tsx`.
  - A row in Settings, plus `src/lib/documentPicker.ts`, `src/lib/documents.ts` and `src/lib/api/documents.ts`.
  - A PDF sent in chat offers **"Save … to My files"** (`chat.tsx`).
- Backend files:
  - Models and storage: `app/models/document.py`, `document_chunk.py`, `app/repositories/document_repository.py`, migration 015.
  - Text reading and the service: `app/integrations/document_text.py`, `app/domain/documents.py`, `app/services/documents.py`.
  - Cooper's tools: `app/services/assistant/document_tools.py`.
  - HTTP: `app/schemas/documents.py`, `app/api/v1/endpoints/documents.py`.

## 5. Request 4a: files and links Cooper can send (ADR-050)

The problem: applying for a job means sending your resume, as a file or a link, and Cooper could do neither. Only the text of an upload was kept, and nothing stored a Drive link.

### 5.1 Files are kept, not just their text (backend)

- New table **`document_files`**: one row per document holding the original bytes (`bytea`). It is a separate table so that listing and reading documents never loads the bytes, and it is deleted with its document. A new column **`documents.has_file`** records whether the file is kept.
- **Storage limit:** 50 MB per user (`DOCUMENT_STORAGE_MAX_BYTES`). Past that, an upload is refused with HTTP 413 and a message like "Your files take 48.2 MB of 50 MB. Delete a file to make room."
- **Older documents** (uploaded before this change) have only their text and show as **"Text only"**. Uploading the same file again keeps the file, matched by its SHA-256.
- **`GET /me/documents/{id}/file`** returns the file (name, media type, base64), so the app can open or share it.
- Files:
  - Storage: `app/models/document_file.py` (new), `app/models/document.py`, `app/repositories/document_repository.py` (`add_file`, `file_data`, `stored_bytes`).
  - Service: `app/services/documents.py` (`stored_file`, `attachable`, `attachment`, `_keep_file`, `_check_room`, `DocumentView.has_file`).
  - HTTP and errors: `app/schemas/documents.py` (`has_file`, `DocumentFileResponse`), `app/api/v1/endpoints/documents.py`, `app/domain/errors.py` (`DocumentStorageFullError` → 413).

### 5.2 Saved links (backend)

- New table **`saved_links`** holds the address, a title, and a kind: resume, portfolio, linkedin, github, website, or other.
  - Addresses are normalized: `https://` is added and the host is lower-cased (`app/domain/links.py`). The same address twice is the same link.
  - At most one link is the resume (a partial unique index); marking another turns the previous one into a plain link.
  - Nothing is ever fetched from a link.
- **Kind guessing:** a title containing "resume" or "CV" makes it the resume; linkedin.com, github.com, behance.net and dribbble.com are recognized by their site. A default title is given when none is entered, such as "Resume (Google Drive)".
- **Endpoints:** `GET/POST /me/links`, `PATCH/DELETE /me/links/{id}`.
- Files:
  - Domain and storage: `app/domain/links.py`, `app/models/saved_link.py`, `app/repositories/link_repository.py`.
  - Service and HTTP: `app/services/links.py`, `app/schemas/links.py`, `app/api/v1/endpoints/links.py`.
  - Shared plumbing: `app/domain/enums.py` (`LinkKind`), `app/domain/errors.py` (`InvalidLinkError`), `app/api/dependencies.py`, `app/api/v1/router.py`, `app/bootstrap.py` (`link_service`).
- Links are included in the data export, which also says which documents have a kept file; the bytes themselves are not in the JSON (`app/services/export.py`).

### 5.3 Attaching files to emails (backend)

- **Composio file upload** (`app/integrations/composio.py`, `ComposioClient.upload_file`, `ComposioFile`):
  1. `POST /api/v3.1/files/upload/request` with the toolkit, tool, file name, media type, and MD5.
  2. A `PUT` of the bytes to the returned address, adding `x-ms-blob-type: BlockBlob` when the storage is Azure.
  3. The tool's arguments get `{name, mimetype, s3key}`.
  The Composio API key is sent only to Composio, never to the storage address.
- **References, not bytes** (`app/services/attachments.py`, new):
  - Cooper never sees file contents. Where an action takes a file (Gmail's `attachment`), it writes `{"document": "resume"}` or a document's title.
  - Just before the action runs, `AppAttachments.stage` finds your file, uploads it to Composio for that exact action, and swaps it in.
  - A reference that can't be resolved stops the action with a reason: no such file, only text kept, or deleted since. Nothing is sent without the file you expect.
- **`run_app_tool`** stages files after its confirmation and connection checks (`AppAccess.with_files` in `app/services/assistant/tools.py`).
- **Job application drafts:**
  - When the draft is prepared, references are **pinned to document ids** (`AppAttachments.pin`), and the card lists them (`JobApplicationDraft.attachments`, new `DraftAttachment` in `app/schemas/message_metadata.py`).
  - **Send** stages exactly those files (`ChatService._execute_job_draft` in `app/services/chat.py`).
  - A deleted file makes the send fail with "A file chosen to attach was deleted…".
  - `linkedin_post_url` is now optional, so an application can answer any job post.
- Wiring: `app/bootstrap.py` builds one `AppAttachments` and shares it with the toolbox and `ChatService`. `app/core/exceptions.py` maps `AttachmentUnavailableError` → 409.

### 5.4 What Cooper is told (assistant prompt 1.9)

- **Context:** documents are listed with marks, e.g. "Resume (resume, attachable)", and saved links with their addresses, e.g. "Resume (resume): https://drive.google.com/…" (`document_label` and `link_label` in `prompts.py`; `chat_turns.py` loads links).
- **Documents paragraph:** an attachable document can be sent as a file by giving `{"document": "<title or resume>"}`; never paste a document's text as an attachment.
- **New links paragraph:** share saved links when they help, written exactly as listed; never invent or shorten one.
- **Job applications:** read the job post when there is one; read the resume; **attach the resume file** when it is attachable and **put the resume link in the body** when one is saved. If neither exists, say so. Say what is attached.

## 6. Request 4b: Apple-style redesign of the whole app

Following Emil Kowalski's skills (`apple-design`, `animate-expo`, `emil-design-eng`, from github.com/emilkowalski/skills). The full spec is in **`AGENTS.md`, section "Design System (iOS design language)"**: read it before changing any UI.

### 6.1 Design tokens

- **`src/constants/colors.ts`** now uses the iOS system palette:
  - tint `#007AFF`;
  - grouped background `#F2F2F7`, with white cells and cards;
  - labels `#000` / `#6E6E73` / `#AEAEB2`;
  - translucent control fills (`rgba(118,118,128,0.12)` …), so controls read the same on white and on gray;
  - hairline separators `#C6C6C8`;
  - system green, orange, red, teal, indigo, purple, pink, and grays;
  - a scrim for sheets, and a dark HUD for toasts.
  Every old token name (`primary`, `textSecondary`, `iconDark`, …) still works and points at the new palette, which is why every screen changed color at once.
- **`src/constants/theme.ts`:**
  - **`Typography`:** the iOS text styles at their real sizes, from large title 34 down to caption 11, with tracking per platform (San Francisco's on iOS, slightly tighter large text with Roboto).
  - **`Radius`** plus **`continuous`**, Apple's squircle corners on iOS.
  - **`Hairline`** and **`ScreenMargin`** (16).
  - **`Motion`:**
    - strong ease-out `(0.23,1,0.32,1)`, ease-in-out `(0.77,0,0.175,1)`, the iOS sheet curve `(0.32,0.72,0,1)`;
    - press 120 ms;
    - springs given as perceptual duration plus damping ratio.
  - **`Elevation`:** soft shadows for floating menus and toasts.

### 6.2 Shared components (`src/components/ui/`, all new)

| Component | What it does |
| --- | --- |
| `PressableScale` | Every tappable surface that is not a list row: shrinks to 97% the moment a finger lands (not when it lifts), 120 ms, as a Reanimated CSS transition; dims instead with Reduce Motion; 44 pt touch targets; a finger drifting a little doesn't cancel. |
| `AppText` | Text in an iOS text style and a label color. |
| `Button` | filled / tinted / gray / plain / destructive; large 50, medium 44, small 32 capsule; loading spinner; icon. |
| `IconButton` | Round glyph buttons (bars, toolbars) with 44 pt targets, optional badge and selected state. |
| `ListSection`, `ListRow`, `IconTile` | iOS Settings-style inset-grouped lists: uppercase section headers, footers, colored icon tiles, values, chevron/check/switch accessories, destructive and "action" rows; rows highlight instantly on touch and fade out on release (like iOS cells, not scaling); separators inset past the icon. |
| `Card` | White rounded surface on the gray background; pressable cards scale to 98%. |
| `SegmentedControl` | iOS segmented control: white thumb sliding on a gray track (ease-in-out, 250 ms), selection haptic, optional badge counts. |
| `AppSwitch` | Platform switch in iOS green with a selection haptic. |
| `BottomSheet` | Sheets for editors and menus: rises on a critically damped spring; drag the grabber or title bar to dismiss using **momentum projection** (a quick flick dismisses even from a few points) and **rubber-banding** past the top; springs home with the finger's velocity and a light haptic; interruptible mid-flight; cross-fades with Reduce Motion; Cancel / Save in the title bar; keyboard-aware; `dismissible={false}` while a save is in flight. |
| `EmptyState` | Glyph in a soft circle, a title naming what's missing, one sentence, at most one action. |
| `ScreenHeader`, `LargeTitle`, `useScrollY` | iOS navigation bar for pushed screens: round back button, centered title; with a large title, the small title and hairline fade in only once the large title scrolls under the bar. |

- **`src/lib/haptics.ts`** (new): `selection`, `light`, `medium`, `success`, `warning`, and `error`.
  - **Rules:** one haptic per action, fired on the same frame as the visual change, and never on scroll, tab switches, toasts, or entrances.
  - **Loading:** `expo-haptics` is loaded behind a guard, so an older app build without the native module doesn't crash; haptics are just silent there.

## 15. Known limitations and follow-ups

**Memory and documents (requests 3 and 4):**
- Memories appear about 5 minutes after a chat goes quiet, not instantly.
- Duplicate thresholds (0.8 / 0.45) are starting values; tune them on real data.
- Existing duplicates and existing proposed memories stay until handled in To review.
- Document search is by words only, not by meaning.
- Scanned PDFs need `DOCUMENT_VISION_FALLBACK`. Images are not documents.
- Files live in Postgres. With many users or large files, move them to object storage behind the same `DocumentService` methods.
- A file can be attached only where the app action accepts one (Gmail does); otherwise Cooper shares the link.

**Redesign (request 4b):**
- **Light mode only.** Dark tokens exist, but no dark appearance was built (`app.json` is light).
- **Custom row parts were built per screen.** The helpers made some parts locally that could become shared components: a round check (Today and Tasks), inset cells for long virtualized lists (Memories), and a standalone section header.
- **Haptics need the new APK.** They are silent until it's built.
